# 実装計画: アイドルファン向け 島マップSNS（MVP）

最終更新: 2026-10-11

## 0. 決定事項のまとめ

### プロダクト

| 項目 | 決定 |
| --- | --- |
| MVP機能 | テキスト投稿、タイムライン、タグ絞り込み、島マップ、いいね |
| MVPに入れないもの | DM、通知、通報、NGワード |
| 島 | 1グループ＝1島。本番での島の追加はDBを直接操作する |
| トップページ `/` | 海に島が並ぶ世界地図。島をクリックするとその島へズームする |
| タグ | 島ごとに独立（島Aの「自己紹介」と島Bの「自己紹介」は別レコード） |
| タグ付け | 本文中の `#タグ` を解析して付ける（Twitterと同じ書き方）。存在しないタグは自動で作る。詳しい規則は「ハッシュタグの解析規則」 |
| タグなし投稿 | その島のグローバル（全投稿）タイムラインにだけ表示する |
| メンバータグ | 話題と同じ `tags` テーブルで管理し、`kind = 'member'` で区別する。島の中央の固定位置に表示し、上位20件の集計には含めない |
| 島に並べる話題タグ | 直近7日間の投稿数で上位20件。結果は5分キャッシュする |
| 上位20件以外のタグ | タグ検索か、投稿内のタグをタップして開く。島はズームせず、タイムラインだけ切り替える |
| ズーム | 世界 → 島 → 家（タグ）の3段階。状態はURLで持ち、スムーズに遷移させる |
| レイアウト | PC優先。上に島マップ、下にタイムライン |
| 家・島の絵 | SVGを手続き生成する（Claude作成）。後でAI生成画像に差し替えられるよう `image_url` 列を用意する |
| リアルタイム更新 | なし。手動更新と無限スクロールで対応する |
| 閲覧 / 投稿 | 閲覧はログイン不要。投稿といいねはログインが必要（ユーザー名＋パスワード。詳細は [plan-account.md](plan-account.md)） |
| 削除 | 論理削除（`deleted_at`） |
| 言語 | 日本語のみ |
| 規模 | 10ユーザー、1日100投稿。集計は都度 `COUNT` で行い、キャッシュで十分とする |

### 回答がなかった項目の扱い（仮定）

- **家の配置（B2）**: 島に固定スロットを20個置き、順位に応じて割り当てる。順位が変わったら家を新しいスロットへアニメーションで移す。
- **d3の使い方（D5）**: 上の「技術」表のとおり。
- **Vercelのプレビューデプロイ**: `dev` ブランチのDBにつなぐ。本番DBは本番デプロイからしか触らない。
- **世界地図（`/`）の下のタイムライン**: 全島の投稿を新しい順に表示し、各投稿に島名のバッジを付ける。
- **投稿フォームの位置**: 島ビュー（`/i/[island]` 以下）にだけ表示する。タグページで開いた場合は、本文の末尾に ` #タグ名` を入力済みにする。
- **投稿の制約**: 本文はハッシュタグを含めて1〜280文字。投稿の編集はできず、自分の投稿だけ削除できる。
- **タグ名の正規化**: NFKC正規化と英字の小文字化を行う。結果を `normalized_name` 列に入れ、島内で一意にする。表示名は最初に作られたときの表記を使う。MVPではタグ名を変更できないため、URLが変わることはない。

### ハッシュタグの解析規則

解析は `features/tags/parse.ts` の1つの関数で行う。投稿時のタグ登録と、表示時の本文リンク化の両方で同じ関数を使い、結果がずれないようにする。

- **開始記号**: 半角 `#` と全角 `＃` のどちらでもよい。
- **直前の文字**: 行頭、空白、または記号でなければならない。`abc#tag` や URL 内の `/#anchor` はタグにしない。
- **使える文字**: 文字（ひらがな、カタカナ、漢字、英字など）、数字、`_`、長音 `ー`。それ以外の文字（空白、句読点、`#` など）でタグが終わる。
- **数字だけのタグ**: `#123` はタグにしない。
- **長さ**: 正規化後に1〜30文字。31文字以上はタグにせず、ただの文字として扱う。
- **重複**: 正規化後の名前が同じタグは1つにまとめる。
- **個数**: 1投稿で先頭から10個までをタグにする。11個目以降は本文には残すがリンクにはしない。
- **入力補助**: 本文で `#` を打つと、島内の既存タグを候補として表示する。

## 1. 画面とURL

```
/                         世界地図（全島）＋ 全島タイムライン
/i/[island]               島ビュー（メンバー中央＋上位20の家）＋ 島のグローバルタイムライン
/i/[island]/t/[tag]       家にズームした状態 ＋ タグで絞ったタイムライン
                          （上位20以外のタグでは島はズームしない）
/dev/islands              島エディタ（ローカル専用。本番では notFound を返す）
/dev/islands/[island]     島の編集（名前、世界地図上の座標、メンバータグとその配置）
/u/[username]             プロフィール（推しグループと推しメンバー。本人なら編集）
```

- `[island]` には `islands.slug`（英小文字とハイフン）を使う。
- `[tag]` には `tags.normalized_name` を URL エンコードした値を使う。

## 2. 遷移をスムーズにする仕組み

ページを移動してもマップを作り直さないことが一番重要。

1. `app/(main)/layout.tsx` にマップ（`<MapCanvas>`、Client Component）を置く。レイアウトは遷移しても再マウントされないので、SVGとズーム状態が残る。
2. `MapCanvas` は `useParams()` で `island` と `tag` を読み、目標のカメラ位置（translate と scale）を計算する。計算した位置へ `d3-zoom` の `transition()` で約600msかけて補間する。ブラウザの戻る・進む操作でも同じ処理で動く。
3. 家や島をクリックしたら、まずズームを開始し、同時に `router.push(url, { scroll: false })` を呼ぶ。ルートの解決を待たずにズームが始まる。
4. タイムラインは `page.tsx` 側に置く。切り替え中は `loading.tsx` でスケルトンを出す。家やタグのリンクにはホバー時に prefetch をかける。
5. 遷移中もユーザーは自由にパン・ズームできる。URLが変わったときだけ、カメラを目標位置へ戻す。
6. マップを表示するデータ（島一覧、上位20件、メンバー）は、レイアウトのServer Componentでまとめて取得して渡す。上位20件はキャッシュから返す。

## 3. マップの描画

- **世界地図**: 海の上に島を `islands.world_x` / `world_y` の位置に置く。島の形は島IDをシードにした、ノイズ入りの円形で手続き生成する。
- **島ビュー**:
  - 中央の広場にメンバーの家を置く。位置は `tags.position` に保存した島内座標で、島エディタで調整する。
  - その周りの2重のリングに、話題タグのスロットを20個置く。順位が高いほど内側に置く。
  - 上位20件に満たない場合は、空いたスロットに家を置かない。
- **家**:
  - 色や屋根の形を、タグIDのハッシュから決める。
  - 家の下にタグ名と投稿数のラベルを付ける。
  - `image_url` に値があれば、その画像を `<image>` で優先して表示する（AI生成画像を後で差し込むため）。
- **アクセシビリティ**: 家は `<a>` ＋ `role="link"` にし、Tabキーで移動できるようにする。キーボードのフォーカス時にも家をハイライトする。
- **負荷**: 1島に表示する家は20件＋メンバー数件、世界地図の島も数個なので、SVGで問題ない。

## 4. データモデル（Drizzle）

```
islands
  id uuid PK, slug text UNIQUE, name text, description text?,
  world_x real, world_y real, theme jsonb?, image_url text?,
  created_at timestamptz

users
  id uuid PK, username text UNIQUE(lower), password_hash text, display_name text,
  avatar_url text?, created_at, updated_at, deleted_at?

sessions / login_attempts / user_favorite_islands / user_favorite_members
  plan-account.md の4章を参照

tags
  id uuid PK, island_id FK→islands, name text, normalized_name text,
  kind enum('member','topic') default 'topic',
  position jsonb?   -- メンバーの島内座標 {x,y}
  image_url text?, created_at
  UNIQUE(island_id, normalized_name)

posts
  id uuid PK, island_id FK, author_id FK→users, body text,
  created_at, deleted_at?
  INDEX(island_id, created_at DESC, id DESC)
  INDEX(created_at DESC, id DESC)   -- 全島タイムライン用

post_tags
  post_id FK, tag_id FK, PK(post_id, tag_id), INDEX(tag_id, post_id)

likes
  user_id FK, post_id FK, created_at, PK(user_id, post_id), INDEX(post_id)
```

- **ページング**: `(created_at, id)` を組にしたカーソル方式。カーソル文字列は base64 でエンコードする。
- **上位20件のクエリ**: `post_tags` と `posts` を結合し、条件 `island_id = ?`、`kind = 'topic'`、`deleted_at IS NULL`、`created_at >= now() - 7 days` で絞って `GROUP BY tag` し、`COUNT DESC` で並べて先頭20件を取る。同数の場合は最新の投稿が新しいタグを上にする。
- **いいね数**: タイムライン取得時にサブクエリで `COUNT` する。今の規模ならカウンター列は不要。

### 将来の拡張に備えた点

- **アカウント機能**: [plan-account.md](plan-account.md) で計画済み。`bio` などは今後 `users` に列を足して対応する。
- **スケジュール機能**: `events` テーブルと `event_tags(event_id, tag_id)` テーブルを作る。島の上に「今日の予定」を重ねて表示できるよう、`MapCanvas` は描画レイヤーを分けた構成にしておく。
- **返信**: `posts.parent_id` 列を追加する。DMは別のテーブル群で作る。
- **モデレーション**: `reports` テーブルを追加する。既に論理削除を前提にしているので、そのまま組み込める。
- **AI生成画像**: `islands.image_url` と `tags.image_url` に値を入れれば、描画側が自動で切り替える。

| 7-4 | 本番DBにマイグレーションを適用し、島を手動で投入してリリースする | 本番で一通り操作できる |

### 依存関係

```
0 → 1 → 2 → 3 ─┐
          1 → 4 → 5 → 6
               3,5 → 7
```

Phase 3（タイムライン）と Phase 4（マップの描画）は、Phase 1 が終われば並行して進められる。

## 7. リスクと対策

| リスク | 対策 |
| --- | --- |
| 遷移時のカクつき | マップをレイアウトに常駐させ、ズームはURLを変える前に開始する（2章） |
| Neonの初回接続が遅い | HTTPドライバを使い、上位20件はキャッシュする |
| 実在アイドルを扱う | 公式画像は使わない。誹謗中傷対策（通報、NGワード）はMVPの直後に優先して検討する |
| 将来AI画像に切り替える | 描画は `image_url` があれば画像、なければSVGにフォールバックする作りで、切り替えを吸収する |
